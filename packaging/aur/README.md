# AUR package

`PKGBUILD` and `.SRCINFO` are generated by
`scripts/packaging/update-manifests.ts` from the release's `amd64.deb` — never
edit them here. The `.deb` is repackaged rather than rebuilt from source so the
AUR package tracks the exact artifact every other channel ships.

## Install

```sh
paru -S storyforge-bin    # or: yay -S storyforge-bin
```

## How the update reaches the AUR

The `aur` job in `.github/workflows/distribute.yml` regenerates the PKGBUILD
(recomputing the checksum from the release asset), regenerates `.SRCINFO`, and
pushes both to `ssh://aur@aur.archlinux.org/storyforge-bin.git`. `pkgver` and
`pkgrel` are reset to the release version and `1` on every bump.

## One-time setup (human)

1. Create an SSH key for the CI runner and add the public key to your AUR
   account (AUR → My Account → SSH Public Key):

   ```sh
   ssh-keygen -t ed25519 -C "storyforge-ci" -f ./aur_deploy -N ""
   ```

2. Store the **private** key as the `AUR_SSH_PRIVATE_KEY` repository secret.
3. Push the package once by hand (or let the next release do it):

   ```sh
   git clone ssh://aur@aur.archlinux.org/storyforge-bin.git
   cp packaging/aur/PKGBUILD packaging/aur/.SRCINFO storyforge-bin/
   cd storyforge-bin && git add . && git commit -m "upgpkg: storyforge-bin 2.0.11" && git push
   ```

The first push creates the package. Without the secret the job is skipped with a
notice, so a missing key never fails a release.

## Notes

- `arch=('x86_64')` only: the release also ships an `arm64` deb, but AUR users on
  aarch64 are rare enough that the extra `pkgbuild` logic has not been worth it.
  Say so if that changes.
- `options=('!strip')` keeps the packaged binaries byte-identical to the release
  artifact — the point of `-bin` is repackaging, not rebuilding, so makepkg has
  nothing useful to do to the payload.
- A `storyforge-git` package (building from source) is deliberately not
  provided: it would need a full Rust toolchain and a `bun` build in `build()`,
  which is what the Flatpak and Nix routes are for.
