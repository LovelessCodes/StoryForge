# Homebrew cask

`Casks/storyforge.rb` is generated by `scripts/packaging/update-manifests.ts` from
the release artifacts — never edit it here, edit the template in that script.

## Install

```sh
brew trust lovelesscodes/tap      # Homebrew requires trusting a third-party tap once
brew install --cask lovelesscodes/tap/storyforge
```

The tap-qualified name auto-taps `LovelessCodes/homebrew-tap` on first use, so
nobody needs a separate `brew tap` step.

## One-time setup (human)

The cask is generated here and has to live in a tap repository. The tap
exists; only the token is still needed:

1. Create a fine-grained PAT with `Contents: read and write` on
   `LovelessCodes/homebrew-tap` and `LovelessCodes/scoop-bucket` (see
   `packaging/scoop/README.md`) and store it as the `PACKAGING_TOKEN` repository
   secret.
2. Until then, seed the tap by hand after a release:

   ```sh
   bun scripts/packaging/update-manifests.ts --only homebrew
   git clone git@github.com:LovelessCodes/homebrew-tap.git
   cp packaging/homebrew/Casks/storyforge.rb homebrew-tap/Casks/
   cd homebrew-tap && git add Casks && git commit -m "storyforge 2.0.11" && git push
   ```

The `homebrew` job in `.github/workflows/distribute.yml` then keeps the tap in
step with every published release: it regenerates the cask, recomputes both dmg
hashes, and pushes only when the file actually changed. A missing
`PACKAGING_TOKEN` skips the job with a notice instead of failing the release.

## Why the cask looks like this

- `auto_updates true` — the app ships a Tauri updater. Without it Homebrew would
  keep offering its own (older) download as an "upgrade" and fight the in-app
  updater that already installed a newer version.
- `zap` deliberately leaves `~/Library/Application Support/StoryForge` alone:
  that directory holds profiles, worlds and downloaded game versions, so
  uninstalling the app must not delete the user's data.
- Both architectures get their own URL and hash, because the app is not a
  universal binary.
- `depends_on :macos` / `auto_updates` / URL grouping are what `brew style`
  enforces for cask taps; the generator output passes
  `brew style --cask` and `brew audit --cask --new` locally.

## Not in homebrew-cask (yet)

The official `Homebrew/homebrew-cask` repository requires the app to be signed
with a Developer ID and notarized, and to meet its notability bar. Neither is
true today (`signingIdentity: "-"` in `src-tauri/tauri.conf.json` is ad-hoc
signing), so this stays a first-party tap until notarization lands — at which
point the same file can be submitted there unchanged.
